# Chatgpt for accounting测评

用合成账务材料测试 Accounting 在什么条件下会漏报、误报、错误匹配、遗漏范围字段或给出不可复核的证据。仓库同时保存题目、评分依据、真实交付物与复核结论，方便第三方拿同一份答卷重新算分。

**第一次看项目**，从[工作 SOP](SOP.md)开始。想核对某个结论，可先看[首轮 12 题试评结果](06-results/README.md)，再按题号查[诊断表与证据](07-diagnosis/README.md)。

能力地图的 60 题蓝图是早期设计。实际建库覆盖其中 13 个核心能力点，12 个独立案例各有 6 个变体，共 72 题。开发组 24 题，候选盲测组 48 题。首轮从开发组抽取 12 题，已经全部收卷并完成客观评分，覆盖逐笔银行核对、分次收款核销、票据分录草稿及月结工作簿检查。T002 完成 80 分自动项和 20 分人工项，最终 100 分。其余 11 题的人工分与最终分待评。

首轮 12 份 JSON 中有 5 份漏写主体全称末尾的“（虚构）”，涉及 4 个独立案例中的 2 个。收款核销题 T013、T014、T017 三次出现，月结题 T049、T050 两次出现。T013 的工作底稿写全了主体名称，JSON 交付时漏了括注。T005 的多候选字段口径已裁定，历史客观分保留为 76.6667/80，单题澄清版 T005-r1 供后续回归。T053 的缺数处理和 7,095.00 元行政费用已由独立表格引擎复算，结构化证据引用格式与公式兼容性仍待专业复核。[查看题项证据与归因](07-diagnosis/)

## 从现有答卷重现结果

下载并解压仓库，进入仓库根目录，用 Python 3.10 或以上执行以下命令。Windows 可将 `python` 换为 `py -3`。

```bash
python 05-scoring/verify_release.py
python 06-results/replay.py
```

第一条用参考答卷校验 24 题和评分边界；第二条从首轮 12 道真实答卷重新计算客观分、比较分项并核对文件指纹。两条命令都可离线执行。新发起模型作答的运行条件见[独立作答说明](04-execution/)。

[归档对照表](归档对照表.md)列出原交付物、公开位置与保留范围。候选盲测题保留在评审侧，避免在正式运行前暴露具体材料和标准答案。
