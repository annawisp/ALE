# Chatgpt for accounting测评

用合成账务材料测试 Accounting 在什么条件下会漏报、误报、错误匹配、遗漏范围字段或给出不可复核的证据。仓库同时保存题目、评分依据、真实交付物与复核结论，方便第三方拿同一份答卷重新算分。

**最新结果**　48 道留出题全部独立交卷，客观均分 **78.24/80**。27 份答卷漏写主体全称，覆盖 5 个业务案例。可直接预览[盲测初步报告](06-results/blind48/README.md)和[48 题逐题成绩](06-results/blind48/scores.csv)。了解操作流程见[工作 SOP](SOP.md)。

## 截至 2026-11-21 的进展

能力地图的 60 题蓝图是早期设计。实际建库覆盖其中 13 个核心能力点，12 个独立案例各有 6 个变体，共 72 题。开发组 24 题，留出盲测组 48 题。首轮从开发组抽取 12 题，已经全部收卷并完成客观评分，覆盖逐笔银行核对、分次收款核销、票据分录草稿及月结工作簿检查。T002 完成 80 分自动项和 20 分人工项，最终 100 分。其余 11 题的人工分与最终分待评。

首轮 12 份 JSON 中有 5 份漏写主体全称末尾的“（虚构）”，涉及 4 个独立案例中的 2 个。收款核销题 T013、T014、T017 三次出现，月结题 T049、T050 两次出现。T013 的工作底稿写全了主体名称，JSON 交付时漏了括注。T005 的多候选字段口径已裁定，历史客观分保留为 76.6667/80，修订版 T005-r1 已独立复测，客观分为 80/80。T053 的三处区间引用违反逐格填写要求。五组独立复算支持工作簿业务计算正确，历史评分器少给的 5 分归入评分器核验局限。现行客观评分基线 v1.2 在同一答卷上给 70.7143/80，历史记录为 65.7143/80。[查看题项证据与归因](07-diagnosis/)

**盲测与初评**　托管 Codex 在每个独立会话中使用官方 Accounting 1.0.1，8 个留出业务案例各运行 6 道变体，合计交付 102 份文件。客观分按 v1.2 计算，AI 对底稿另给建议分。两项有分歧的评分口径按原分保留，本批跳过人工核验，正式百分制成绩留空。[能力诊断](07-diagnosis/README.md) · [修订题预检实答](06-results/T005-r1/README.md)

## 从现有答卷重现结果

下载并解压仓库，进入仓库根目录，用 Python 3.10 或以上执行以下命令。Windows 可将 `python` 换为 `py -3`。

```bash
python 05-scoring/verify_release.py
python 06-results/replay.py
```

第一条校验公开开发题的参考答案与评分边界。第二条从首轮 12 份真实答卷重新计算现行客观分，并核对历史分、分项和文件指纹。两条命令都可离线执行。新发起模型作答的运行条件见[独立作答说明](04-execution/)。

[归档对照表](归档对照表.md)列出原交付物、公开位置与保留范围。留出批次公开匿名逐题成绩。能还原试题的原件、首次实答及配套标准答案由评审侧保存。
