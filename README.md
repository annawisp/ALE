# Chatgpt for accounting测评

用合成账务材料测试 Accounting 在什么条件下会漏报、误报、错误匹配、遗漏范围字段或给出不可复核的证据。仓库同时保存题目、评分依据、真实交付物与复核结论，方便第三方拿同一份答卷重新算分。

**第一次看项目**，从[工作 SOP](SOP.md)开始。想核对某个结论，可先看[六题试评结果](06-results/README.md)，再按题号查[诊断表与证据](07-diagnosis/README.md)。

## 截至 2026-11-20 的进展

能力地图的 60 题蓝图是早期设计。实际建库覆盖其中 13 个核心能力点，12 个独立案例各有 6 个变体，共 72 题。开发组 24 题，候选盲测组 48 题。首轮 12 题从开发组抽取，目前有 6 题实答，分属银行核对和月结两个案例族。T002 已完成 80 分自动项和 20 分人工项，最终 100 分；其余五题目前只有客观分。

已观测到的一个具体偏差是月结题 T049 和 T050 的主体全称均漏写“（虚构）”。同一案例族内复现两次，两个入口各一次；跨主体复现仍待验证。T053 体现了另一类情形，受影响指标保留待核，未受影响的行政费用算得 7,095.00 元；独立表格引擎复算通过，评分器对函数与引用范围的兼容性影响了客观分。[查看题项证据与归因](07-diagnosis/)

## 从现有答卷重现结果

下载并解压仓库，进入仓库根目录，用 Python 3.10 或以上执行以下命令。Windows 可将 `python` 换为 `py -3`。

```bash
python 05-scoring/verify_release.py
python 06-results/replay.py
```

第一条用参考答卷校验 24 题和评分边界；第二条从六道真实答卷重新计算客观分、比较分项并核对文件指纹。两条命令都可离线执行。新发起模型作答的运行条件见[独立作答说明](04-execution/)。

[归档对照表](归档对照表.md)列出原交付物、公开位置与保留范围。候选盲测题保留在评审侧，避免在正式运行前暴露具体材料和标准答案。
