# 六道开发样例的真实答卷

六题覆盖两个业务案例。银行对账三题属于同一案例族；月结工作簿三题属于另一案例族。同一案例族下替换输入或错误类型，有助于定位触发条件。跨企业、跨场景的稳定性和整套插件通过率仍待独立样本验证。

| 题号 | 能力场景 | 运行渠道 | 客观分 / 80 | 如何解读 |
|---|---|---|---:|---|
| T001 | 常规逐笔银行对账 | ChatGPT 网页版 | 80.0000 | 8 笔银行流水均完成匹配，9 个题项通过自动检查。 |
| T002 | 银行对账存在金额差异及未匹配项 | ChatGPT 网页版 | 80.0000 | B003 金额差异、B007 未匹配均识别。另有已完成人工复核的历史记录，人工 20/20、最终 100/100。 |
| T005 | 对账有多个候选 | 托管 Codex | 76.6667 | 答卷将 B003 标为待核、差额留空，并列出两个候选 ID。评分器要求此字段为空；应先澄清候选与已确认匹配的字段定义。 |
| T049 | 正常月结公式与证据追溯 | ChatGPT 网页版 | 77.5000 | 四项数值、状态及工作簿通过。结构化主体字段漏“（虚构）”，扣 2.50 分。v1.1 接受已验证的间接证据链；v1.0 客观分为 75.3571。 |
| T050 | 月结公式漏加或重复加总 | 托管 Codex | 77.5000 | 两条错误公式均修正，保留其余公式。主体字段同样漏“（虚构）”。同一月结案例族的两次复现可用于设计跨案例验证。 |
| T053 | 明细缺失与可完成事项 | 托管 Codex | 65.7143 | 行政费用独立算出 7,095.00 元，受影响的三项留待补。数值与状态正确。结构化证据使用单元格区域，与机器逐格引用要求有差异。评分器未覆盖 COUNT 等函数，独立表格引擎对五组输入的复算结果均与预期一致。 |

## 文件与验证

- `scores.csv` 列出渠道、客观分、历史人工分及交付文件数。人工分空白表示该栏未评。
- `pilot_evidence.zip` 下，`submissions/<题号>/` 收录原始 JSON、工作底稿及三份 Excel；`records.json` 列出运行渠道与逐文件 SHA-256。六题共 15 份答卷文件。
- `objective/` 存档每题客观评分分项、门槛及失败项；`historical/` 收录匿名化的 T002 人工得分摘录、T049 规则变更前历史分；`independent_checks/` 提供 T050、T053 已执行的工作簿扰动复算记录。独立复算记录与原评分器的输出分别保留。
- `replay.py` 在临时目录里核对答卷指纹，调用公开 v1.1 评分器，逐题比较客观分、门槛和扣分细目。复算不调用模型。人工分另从历史摘录查看。

在仓库根目录执行：

```bash
python3 06-results/replay.py
```

网页三题由已选择 Accounting 的 ChatGPT 对话完成。其余三题由各自独立的托管 Codex 子会话使用 Accounting 1.0.1 技能指令作答，各题文件计算进程限制读取范围、分离可写输出并禁用套接字；宿主账户的全部权限隔离未独立验证。两类渠道的具体模型快照均未留存。六题均无本地 Docker 生成的答卷。本地 CLI 的基础设施失败排除在插件能力样本之外。

此公开版本仅保留归因和复算所需材料。网页截图、账户信息、个人签名、会话标识、私有本机日志等不在公开记录中。SHA-256 用于复核下载后文件的一致性。
