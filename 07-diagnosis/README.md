# 首轮 12 题能力诊断

最清楚的一项短板是结构化主体名称填写不全。12 份有效开发答卷都要求精确填写主体全称，其中 5 份的 `response.json` 省略了“（虚构）”。这个问题已在分次收款和月结两个独立业务案例复现。T013 的工作底稿首页写“岚序机器人（虚构）”，JSON 却写“岚序机器人”，可以将该次遗漏定位在结构化交付环节。

T013、T014、T017、T049、T050 每题因名称不全扣 2.50 分。该发现限于受测样本。网页版 3 份答卷与托管 Codex 9 份答卷涉及的具体题目不同，未做同题配对，不能从出现次数推断某个运行入口的效果或生产环境的发生率。

## 关键发现与证据

- **T005 的分歧已经裁定。** 插件将 B003 标为待核，差额为 null，同时在账簿 ID 字段列出两个候选。旧题面未明确应否列候选，首次机器分保留 76.6667/80，不记作强行匹配。新版题面要求该字段仅放已确认的 ID；待核时填空列表，候选及原因写入底稿。新版实答应另计轮次。
- **分次收款与票据分录的 28 个新增题项**在数值或分录、状态方面均符合参考。T014 的部分核销余额为 2,000.00 元；T017 为有歧义的两张发票保留待核，同时完成另两张。T038、T041 各保留一张问题票据的空分录，其他五张继续制单。对应材料例证、证据是否充分和论证质量可以分别复核。
- **T053 的 65.7143/80 需拆开解读。** 三项受缺数影响的汇总或比率列“待补资料”，行政费用得出 7,095.00 元，数值与状态分别得到 30/30、10/10。三条区域引用不符合当前单格格式，证据位置为 0.7143/10。工作簿使用 COUNT、ROWS，评分器不能完整验证，交付项得 5/10。五组输入经独立表格引擎复算均符合预期；公式业务含义及证据是否足够仍待专业复核，原分与裁定应并列留存。
